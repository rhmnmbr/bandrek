# Bandrek

Windows desktop app for running a bimbel (tutoring center): schedule learning activities on a calendar, record attendance, and track which student has covered which material.

> **Status:** interactive prototype finished in Claude Design. Implementation is starting with **UI slicing** of the desktop client against a mock data layer. The server has not been started.

## Architecture

```
Tauri desktop client (Windows)  ── HTTPS ──▶  ASP.NET Core 10 API  ──▶  PostgreSQL
React + TypeScript                           Ubuntu VPS · Docker Compose · Caddy
```

- **One bimbel per deployment.** Several operators log in to one shared server. A future second customer gets its own instance from the same code.
- **Online-only.** The client keeps a read cache so data stays viewable when the connection drops. All writes are disabled while offline.
- **The server owns the business rules.** The client only validates form shape. Derived status, allowed actions, conflict detection, and matrix cell state come from the API.
- **One contract.** The server generates `contract/openapi.json`, which is committed. The client generates its types and query hooks from it.

Details and reasons: [`docs/ARCHITECTURE.md`](docs/ARCHITECTURE.md).

## Tech stack

**Desktop:** Tauri 2, React, TypeScript, Vite, Tailwind CSS, shadcn/ui (themed from DESIGN.md), React Router, TanStack Query, React Hook Form + Zod, date-fns.

**Server:** ASP.NET Core 10 (LTS) Minimal APIs, EF Core 10 + Npgsql, ASP.NET Core Identity, built-in OpenAPI.

**Infrastructure:** Ubuntu VPS, Docker Compose, Caddy (automatic HTTPS), PostgreSQL.

## Development

### Desktop

Prerequisites (Windows):
- **Node.js** — the version in `desktop/.nvmrc` (latest LTS). Use any version manager that reads `.nvmrc` (fnm, nvm) or install that version directly. `npm install` refuses to run on the wrong version.
- **Rust** — stable, pinned by `desktop/src-tauri/rust-toolchain.toml`; rustup picks it up automatically.
- Microsoft C++ Build Tools, and the WebView2 runtime (bundled with Windows 11).

```bash
cd desktop
npm install
npm run dev          # browser, mock data
npm run tauri dev    # desktop window
```

> Commands will be confirmed once the project is scaffolded (slicing task, phase 1).

Not started.

## Conventions

- **Versions:** always the latest **stable** release of every library, framework, and toolchain — never alpha, beta, RC, or preview. For Node.js that means the latest LTS line. Look versions up in the registry instead of assuming them. Upgrades are deliberate and committed separately.
- **Toolchain pins:** `desktop/.nvmrc`, `desktop/src-tauri/rust-toolchain.toml`, `server/global.json`. Version-manager setup on your own machine stays out of the repo.
- **Packages:** npm (not pnpm). Lockfiles are committed: `package-lock.json`, `Cargo.lock`, and NuGet `packages.lock.json` (enabled with `RestorePackagesWithLockFile`).
- **Releases:** tagged per component, e.g. `desktop-v1.3.0` and `server-v1.2.0`. The desktop ships through the Tauri auto-updater; the server rejects clients older than its minimum supported version.
- **Language:** the UI is in Bahasa Indonesia. Code and technical specs are in English; business rules and UI copy are in Indonesian.
- **Configuration:** nothing about the bimbel (name, logo, domain, timezone) is hardcoded. It comes from deployment config. The server address is entered in the client on first launch.
